# 04 — Host↔Firmware command protocol (H2C / C2H) — RTL8852B, FW 0.29.29.18, station mode

Source: `reference/linux-v7.2.7/drivers/net/wireless/realtek/rtw89/` (all paths below are relative to it).
Path followed: RTL8852B (`chip_gen = RTW89_CHIP_AX`), PCIe, CV_B, RFE 1, FW 0.29.29.18, one
`NL80211_IFTYPE_STATION` vif, no P2P/AP/MLO/WoWLAN/MCC, LPS disabled.

Terminology used here:

* **H2C** = host-to-chip firmware command. Two transports exist:
  * **packet H2C** — a DMA buffer on the PCIe FWCMD TX ring (TX channel 12). This is the normal path.
  * **register H2C** ("h2creg") — a 16-byte mailbox at 0x8140..0x814C + trigger at 0x8160, answered by a
    16-byte "c2hreg" mailbox at 0x8150..0x815C + 0x8164. Used by 8852B only for two messages.
* **C2H** = chip-to-host firmware event. Packet C2Hs arrive on the normal PCIe RX ring (RXQ) with RX
  descriptor packet type 10; register C2Hs are polled.
* cat/class/func = the three-level command id (category 2 bits, class 6 bits, function 8 bits) used by
  both H2C and C2H.
* `rack`/`dack` = the "receive ack" and "done ack" request bits in the H2C header; the firmware answers
  them with C2H `REC_ACK` / `DONE_ACK` events.

Everything numeric below is resolved for 8852B; "AX" branches are the ones taken.

---------------------------------------------------------------------------------------------------

## 0. Executive summary (what a new driver must implement)

1. Build every H2C as `[24-byte TX WD body][8-byte H2C header][payload]`, post it on PCIe TX ring
   CH12 (FWCMD), one TXBD per H2C, kick `R_AX_CH12_TXBD_IDX` (0x1080). No credits; the only flow
   control is the CH12 BD ring depth (§1.5).
2. H2C header: seq increments per H2C (8-bit, wraps); on AX the host must force `rec_ack=1` whenever
   `seq % 4 == 0` (§1.3). Set `done_ack` per the per-command table (§4.1); the host only needs to
   *wait* for acks for: packet-offload add/del, HW-scan start/add-channel/stop, IPS cfg (not used).
3. C2Hs: parse RX desc dword0 RPKT_TYPE (bits 27:24) == 10, strip RX desc (+drv_info+shift), then an
   8-byte C2H header (cat/class/func/len). Station-relevant events: DONE_ACK / REC_ACK (MAC 0/1),
   C2H_LOG (MAC 0/2), PKT_OFLD_RSP (MAC 1/2), SCANOFLD_RSP (MAC 1/9), BCNFLTR_RPT (MAC 1/0xD),
   RA status report (OUTSRC 1/0), coex reports (OUTSRC class 0x10..0x17). Anything else can be
   logged and dropped (§3).
4. Register mailbox is needed for: reading PHY capability at probe (`GET_FEATURE` → `PHY_CAP`), and
   **every scheduler TX stop/resume once FW is running** (`SCH_TX_EN` → `TX_PAUSE_RPT`) — which
   8852B does around every channel switch and around IQK/RX-DCK/DPK/TSSI calibration (§1.6).
5. Minimal station command set (all AX formats): FW log cfg (optional), OFLD_CFG, RF_REG A/B pages,
   role maintain, join info, addr-CAM (+ embedded BSSID-CAM), default CMAC table, assoc CMAC table,
   macid pause(unpause), RA MACIDCFG, sec-CAM (HW crypto), BA-CAM (RX BA), USR_EDCA, RF "get MCC
   channel" notify after RFK. Optional: general-pkt (+packet offload), beacon filter/RSSI/TP offload,
   pkt drop (flush), coex. Skip: beacon update, LPS/IPS, CPU exception, MCC/MRC, WoW, DBCC, TWT.
6. 8852B does **host-side RF calibration** (rtw8852b_rfk.c); none of the `rtw89_fw_h2c_rf_*` RFK
   offload commands (class 0xB) is sent. The only RF-class H2Cs are RF_REG_A/B (table mirror) and
   RF_FW_NOTIFY/GET_MCCCH (§4.17, §4.18).
7. SW scan needs no scan H2C; it only re-sends the addr-CAM (random/scan MAC as source) at start and
   end, plus the per-channel `SCH_TX_EN` register handshake and coex notifications (§5.3).

## 1. H2C transport

### 1.1 Buffer layout on PCIe (FWCMD ring, TX channel 12)

`rtw89_fw_h2c_alloc_skb()` reserves `H2C_HEADER_LEN (8) + chip->h2c_desc_size` headroom
(fw.c:77-94). For 8852B `h2c_desc_size = sizeof(struct rtw89_txwd_body) = 24` (rtw8852b.c:1080,
core.h:1092-1099). The payload is written first, the 8-byte header is pushed by
`rtw89_h2c_pkt_set_hdr()` (fw.c:1604-1627), then the PCIe layer pushes the 24-byte WD body
(`rtw89_pci_fwcmd_submit`, pci.c:1551-1586). The DMA buffer is therefore:

| Offset | Size | Content |
|---|---|---|
| 0x00 | 24 | TX WD body (only dwords 0, 2, 3 written; 1, 4, 5 are zero) |
| 0x18 | 8 | H2C header (§1.2) |
| 0x20 | N | payload (little-endian dwords as documented per command) |

* No WD page / no WD info is used for FWCMD: "FWCMD queue doesn't have wd pages. Instead, it submits
  the CMD buffer with WD BODY only" (pci.c:1596-1604). The TXBD points straight at the skb data.
* TXBD (8 bytes, `struct rtw89_pci_tx_bd_32`, pci.h:1465-1471): `u16 length` = whole buffer length
  (24+8+N); `u16 opt` = `BIT(14)` (LS) | `DMA_HI` in bits 13:6 (bits 39:32 of the DMA address);
  `u32 dma` = low 32 bits of the DMA address (pci.c:1576-1581). One TXBD per H2C.
* Kick: write the host write-pointer (16-bit write) to the CH12 index register
  `R_AX_CH12_TXBD_IDX = 0x1080` (pci.h:553; `__rtw89_pci_tx_kick_off`, pci.c:1332-1345). HW read index
  is bits 27:16 of the same register (`TXBD_HW_IDX_MASK`, pci.h:558).
* Only FWCMD type may use CH12 and FWCMD must use CH12 (pci.c:1646-1653).
* No alignment/padding requirement beyond this is applied by rtw89 (payload length is arbitrary, e.g.
  6-byte general-pkt, 60-byte addr-CAM).

TX WD body values for a normal H2C (`rtw89_core_tx_update_h2c_info` core.c:905-913 sets
`ch_dma = RTW89_DMA_H2C = 12`, `wd_page = 0`, `is_bmc = 0`; everything else zero because
`tx_req` is zero-initialised in `rtw89_h2c_tx` core.c:1336-1375; 8852B's `fill_txdesc_fwcmd =
rtw89_core_fill_txdesc`, rtw8852b.c:914, core.c:1600-1621; bit masks txrx.h:69-97):

| WD dword | Field | Bits | Value |
|---|---|---|---|
| 0 | CHANNEL_DMA | 19:16 | 12 (0xC) |
| 0 | FW_DL | 20 | 0 (1 only for FW-image chunks, §1.4) |
| 0 | WD_INFO_EN / WD_PAGE / WP_OFFSET / HDR_LLC_LEN / HW_SSN | 22, 7, 31:24, 15:11, 3:0 | 0 |
| 1 | — | | 0 |
| 2 | TXPKT_SIZE | 13:0 | 8 + N (H2C header + payload; measured before the WD is pushed) |
| 2 | MACID / QSEL / TID_INDICATE | 30:24 / 22:17 / 23 | 0 |
| 3 | SW_SEQ / AGG_EN / BK | 11:0 / 12 / 13 | 0 |
| 4, 5 | — | | 0 |

So dword0 = `0x000C0000`, dword2 = `8+N`.

Buffer release: completed FWCMD skbs are reclaimed by comparing the host index with the HW index
read back from 0x1080 (`rtw89_pci_txbd_recalc`, pci.c:87-98). rtw89 deliberately keeps the last
`RTW89_PCI_MULTITAG = 8` completed H2C buffers mapped before freeing them (pci.c:100-131,
pci.h:1131). Treat this as a "don't free the most recent 8 FWCMD buffers immediately" rule.

### 1.2 H2C header (8 bytes, `struct fwcmd_hdr`, fw.h:4562-4565, masks fw.h:4601-4611)

| Dword | Bits | Field | Value used |
|---|---|---|---|
| hdr0 | 1:0 | CAT (category) | 0 = TEST, 1 = MAC, 2 = OUTSRC (PHY/RF/BTC) |
| hdr0 | 7:2 | CLASS | per command |
| hdr0 | 15:8 | FUNC | per command |
| hdr0 | 19:16 | DEL_TYPE | `FWCMD_TYPE_H2C = 0` always |
| hdr0 | 23:20 | — | 0 |
| hdr0 | 31:24 | H2C_SEQ | `rtwdev->fw.h2c_seq` (u8) |
| hdr1 | 13:0 | TOTAL_LEN | payload length + 8 (includes this header, excludes WD) |
| hdr1 | 14 | REC_ACK | request C2H REC_ACK (see §1.3 forcing rule) |
| hdr1 | 15 | DONE_ACK | request C2H DONE_ACK |
| hdr1 | 31:16 | — | 0 |

`RTW89_H2C_MAX_SIZE = 2048` (fw.h:329) is the size rtw89 designs around (scan channel list chunking);
the largest normal H2Cs sent to 8852B are RF_REG pages of up to 500 dwords (2000 bytes + 8).

Examples (hdr0 without seq / hdr1): role-maintain `0x00000421 / 0x800C`; addr-CAM `0x00000019 /
0x8044`; CMAC table `0x00000215 / 0x804C`; RA `0x00000006 / 0x0018`.

### 1.3 Sequence number, forced REC_ACK

* `h2c_seq` is incremented after every `rtw89_h2c_pkt_set_hdr()` (fw.c:1626). It is a `u8`
  (core.h:5036) and wraps at 256.
* It is reset to 0 together with `rec_seq`, `h2c_counter`, `c2h_counter` right after a successful FW
  image download, before waiting for FW ready (fw.c:1992-1995). So the first post-download H2C
  (OFLD_CFG, §5.1) has seq 0.
* **AX rule:** if `seq % 4 == 0` the host sets REC_ACK regardless of the caller's choice
  (fw.c:1613-1614). rtw89 does not wait on these acks; the rule appears to be a firmware
  expectation for AX (keep it). Nothing else ever consumes the seq except the scan-event bookkeeping
  (§2.3).

### 1.4 FW-download variant (for completeness; details belong to the FW-download track)

* FW header: `rtw89_h2c_pkt_set_hdr_fwdl()` (fw.c:1629-1645) — cat 1 (MAC), class 3 (FWDL),
  func 0 (FWHDR_DL), current seq *without* incrementing and *without* rack/dack; payload = the FW
  header bytes (possibly truncated, fw.c:1700-1753). WD dword0 FW_DL = 0.
* FW image sections: raw chunks with **no H2C header** (`rtw89_fw_h2c_alloc_skb_no_hdr`), sent with
  `desc_info.fw_dl = 1` → WD dword0 = `0x001C0000` (FW_DL bit 20 + CHANNEL_DMA 12), dword2 = chunk
  length (fw.c:1782-1837, core.c:1353-1354).

### 1.5 Flow control / credits

* There is **no H2C credit counter and no "outstanding H2C" limit** in rtw89 for the packet path.
  `rtw89_h2c_tx()` only checks that the CH12 TXBD ring has a free slot (after reclaiming completed
  descriptors from HW index); if none, `-ENOSPC` "no tx fwcmd resource" (core.c:1361-1365,
  pci.c:1234-1245). Ring depth is `RTW89_PCI_TXBD_NUM_MAX = 256` (pci.h:1122).
* H2Cs are silently dropped (returns 0) if the chip is not powered (`RTW89_FLAG_POWERON` clear,
  core.c:1343-1349).
* The register path has its own handshake (§1.6). A "HALMAC H2C dequeue counter" in 0x1F5[3:0] is
  written only by the register path.
* Sequencing: rtw89 sends H2Cs back-to-back without waiting, relying on in-order FW processing,
  except the few wait-for-ack commands (§2).
* There is no "h2c_prog"/progress counter in rtw89. Debug registers dumped on FW trouble
  (`rtw89_fw_st_dbg_dump`, fw.c:8296-8320; reg.h:208-249): `R_AX_UDM0` 0x1F0 (FW status),
  `R_AX_UDM1` 0x1F4 (FW bad address; bits 15:8 also hold the h2creg/c2hreg counters),
  `R_AX_UDM2` 0x1F8 (EPC/RA), `R_AX_UDM3` 0x1FC (misc), `R_AX_HALT_H2C_CTRL` 0x160,
  `R_AX_HALT_C2H_CTRL` 0x164, `R_AX_HALT_H2C` 0x168, `R_AX_HALT_C2H` 0x16C (SER halt
  handshake; both CTRL registers are zeroed right after the FW header download, fw.c:1776-1777).

### 1.6 Register-based H2C/C2H mailbox

Registers (8852B uses the non-`_V1` set: `rtw8852b_h2c_regs`/`rtw8852b_c2h_regs`, rtw8852b.c:124-132;
chip_info rtw8852b.c:1082-1088; reg.h:242-245, 522-542):

| Name | Addr | Notes |
|---|---|---|
| R_AX_H2CREG_DATA0..3 | 0x8140, 0x8144, 0x8148, 0x814C | 4 dwords host→FW |
| R_AX_C2HREG_DATA0..3 | 0x8150, 0x8154, 0x8158, 0x815C | 4 dwords FW→host |
| R_AX_H2CREG_CTRL | 0x8160 | byte; bit0 `B_AX_H2CREG_TRIGGER`; FW clears to 0 when consumed |
| R_AX_C2HREG_CTRL | 0x8164 | byte; bit0 `B_AX_C2HREG_TRIGGER`; FW sets !=0 when a reply is present, host clears to 0 |
| H2C counter | 0x1F5 bits 3:0 (= R_AX_UDM1 0x1F4 bits 11:8, `B_AX_UDM1_HALMAC_H2C_DEQ_CNT_MASK`) | host increments per h2creg |
| C2H counter | 0x1F5 bits 7:4 (= 0x1F4 bits 15:12, `B_AX_UDM1_HALMAC_C2H_ENQ_CNT_MASK`) | host increments per c2hreg read |
| R_AX_HD0IMR / HD0ISR | 0x8110 / 0x8114, bit0 C2H_INT(_EN) | defined, but rtw89 polls; no IRQ used for c2hreg |

Mailbox word 0 header (both directions): `FUNC` bits 6:0, `LEN` bits 11:8 (number of dwords
including the header dword), C2H additionally `ACK` bit 7 and `SEQ` bits 15:12 (defined, unused)
(fw.h:21-28, 97-102). The header occupies the low 2 bytes (`RTW89_H2CREG_HDR_LEN = 2`).

**Send (h2creg)** — `rtw89_fw_write_h2c_reg` (fw.c:8188-8219):
1. Poll `read8(0x8160) == 0`, every 1 ms, timeout 5 ms (else "FW does not process h2c registers").
2. `w0[6:0] = id`, `w0[11:8] = DIV_ROUND_UP(content_len + 2, 4)`.
3. Write all four dwords to 0x8140, 0x8144, 0x8148, 0x814C.
4. `h2c_counter++`; write it into 0x1F5[3:0] (read-modify-write of that byte).
5. `write8(0x8160, 0x01)`.

**Receive (c2hreg)** — `rtw89_fw_read_c2h_reg` (fw.c:8221-8264):
1. Poll `read8(0x8164) != 0` every 1 µs, timeout 1,000,000 µs for PCIe (`RTW89_C2H_TIMEOUT`,
   fw.h:121) or caller override.
2. Read four dwords 0x8150..0x815C.
3. `write8(0x8164, 0)`.
4. `id = w0[6:0]`; `content_len = w0[11:8]*4 - 2`.
5. `c2h_counter++`; write into 0x1F5[7:4].

Function ids (fw.h:145-169): H2C: 0 LB, 1 CNSL_CMD, 2 FWERR, 3 GET_FEATURE, 4 GETPKT_INFORM,
5 SCH_TX_EN, 6 WOW_TRX_STOP, 7 AOAC_RPT_1, 8 AOAC_RPT_2, 9 AOAC_RPT_3_REQ, 10 WOW_CPUIO_RX_CTRL.
C2H: 0 LB, 1 ERR_RPT, 2 ERR_MSG, 3 PHY_CAP, 4 TX_PAUSE_RPT, 0xA WOW_CPUIO_RX_ACK,
0xC PHY_CAP_PART1, 0xD PS_LEAVE_ACK, 0xFF NULL (initial value).

Messages actually used on 8852B / FW 0.29.29.18:

| Use | H2C | C2H expected | When |
|---|---|---|---|
| PHY capability | GET_FEATURE (3): content_len 0 on AX → LEN=1; `w0[23:16] = part_num = 0` | PHY_CAP (3) | probe: `rtw89_chip_efuse_info_setup → rtw89_mac_setup_phycap` (core.c:7180-7206, mac.c:3177-3336). Part 1 is not requested on AX (mac.c:3329-3331). |
| Scheduler TX enable | SCH_TX_EN (5): content_len 6 → LEN=2; `w0[31:16] = tx_en`, `w1[15:0] = mask`, `w1[16] = band` | TX_PAUSE_RPT (4) — else -EINVAL | Any `rtw89_mac_stop_sch_tx`/`resume_sch_tx` **once `RTW89_FLAG_FW_RDY` is set** (mac.c:3338-3383); before FW is ready the same thing is a plain 16-bit RMW of `R_AX_CTN_TXEN` 0xC348. |

PHY_CAP reply layout (fw.h:30-54): w0[23:16] RX_NSS, w0[31:24] BW, w1[7:0] TX_NSS, w1[15:8] PROT
(1 11n, 2 11ac, 3 11ax, 4 11be), w1[23:16] NIC, w1[31:24] WL_FUNC, w2[7:0] HW_TYPE,
w3[15:8] ANT_TX_NUM, w3[23:16] ANT_RX_NUM, w3[31:24] BAND_SEL. rtw89 uses TX/RX NSS (0 → use chip
default 2), ANT_TX/RX_NUM (1 → antenna B only), PROT (<4 → no EHT) (mac.c:3222-3282).

SCH_TX_EN semantics: `rtw89_mac_stop_sch_tx(sel=ALL)` first reads the current 16-bit
`R_AX_CTN_TXEN` (0xC348, band 0) into `tx_en`, then sends `tx_en=0, mask=0xFFFF`;
`resume_sch_tx` sends the saved `tx_en` with `mask=0xFFFF` (mac.c:3403-3495; `B_AX_CTN_TXEN_ALL_MASK`
= GENMASK(15,0), reg.h:2305). Callers on 8852B: `rtw8852b_set_channel_help` enter/exit around every
channel set (rtw8852b.c:675-697), `rtw8852b_iqk`, `rtw8852b_rx_dck`, `rtw8852b_dpk`,
`rtw8852b_tssi` (rtw8852b_rfk.c:3760-3850).

Not used on this FW: WOW_CPUIO_RX_CTRL (gated off by `NO_WOW_CPU_IO_RX`, mac.c:7302-7303), PS_LEAVE_ACK
C2H (needs `LPS_DACK_BY_C2H_REG`, ps.c:24-25), AOAC reports (WoW).

## 2. Acknowledgement and waiting

### 2.1 What the FW sends back

* REC_ACK (C2H MAC class 0 func 0) for each H2C whose header has REC_ACK=1 (including the forced
  every-4th one).
* DONE_ACK (C2H MAC class 0 func 1) for each H2C whose header has DONE_ACK=1, carrying an 8-bit
  "h2c_return" status (0 = OK).
* Some commands have their own response event instead of/in addition to DONE_ACK: packet offload →
  PKT_OFLD_RSP; scan offload → SCANOFLD_RSP.

Layouts: §3.4.

### 2.2 Wait mechanism in rtw89

`rtw89_h2c_tx_and_wait()` (fw.c:10174-10201) = `rtw89_wait_for_cond_prep()` (arm a condition on a
`rtw89_wait_info`, only one outstanding per wait object; -EPERM if busy), send, then
`wait_for_completion_timeout(RTW89_WAIT_FOR_COND_TIMEOUT = 100 ms)` (core.c:6433-6497,
core.h:4859). The C2H handler calls `rtw89_complete_cond(wait, cond, data)` which only completes if the
armed condition value matches exactly (core.c:6506-6523). `data.err != 0` → -EFAULT.

Condition encoding for `rtwdev->mac.fw_ofld_wait` (fw.h:4712-4728):
`cond = tag * 53 + func`, where 53 = `NUM_OF_RTW89_FW_OFLD_H2C_FUNC` (enum ends after
`TRX_PROTECT = 0x34`). Packet offload: `tag = pkt_id * 3 + op` (op 0 ADD, 1 DEL, 2 READ, fw.h:210-218).
Scan: START = `0*53+0x17`, STOP = `1*53+0x17`, ADD_CH = `0*53+0x16`.

Commands that are waited on (complete list for AX; station-relevant in bold):

| H2C | Waits for | Condition | fw.c |
|---|---|---|---|
| **PACKET_OFLD add** (MAC/9/0x01) | C2H PKT_OFLD_RSP with same id/op; err if `pkt_len==0` | PKT_OFLD(id, ADD) | 6446-6495 |
| **PACKET_OFLD del** | PKT_OFLD_RSP | PKT_OFLD(id, DEL) | 6408-6444 |
| ADD_SCANOFLD_CH (MAC/9/0x16) | DONE_ACK, `return & 0x3F` = err | ADD_CH | 6497-6572 |
| SCANOFLD start (MAC/9/0x17) | DONE_ACK | START | 6681-6789 |
| SCANOFLD stop | SCANOFLD_RSP reason END_SCAN_NOTIFY | STOP | same |
| IPS_CFG (MAC/2/3) | DONE_ACK (`ps_wait`) | — | 10114-10140 (not used: no IPS H2C in this config) |
| TRX_PROTECT | DONE_ACK | — | BE only; returns 0 on AX (fw.c:7037-7038) |
| MCC/MRC/WoW/MLO | various | — | out of scope |

Everything else is fire-and-forget. DONE_ACKs for non-waited commands are parsed and ignored
(mac.c:5494-5555 only acts on class PS/func IPS_CFG and class FW_OFLD funcs 0x16/0x17/0x2c/0x34).

### 2.3 REC_ACK usage

`rtw89_mac_c2h_rec_ack` (mac.c:5458-5491) only increments `scan_info->seq` when it sees a REC_ACK
for MAC/FW_OFLD/SCANOFLD(_BE); SCANOFLD_RSP events are tagged with that seq and events carrying an
obsolete seq are purged (`rtw89_fw_c2h_purge_obsoleted_scan_events`, fw.c:8154-8185). All other
REC_ACKs are ignored.

## 3. C2H transport, header and dispatch

### 3.1 Arrival on PCIe

* C2H packets come on the normal RX ring (RXQ, `RTW89_RXCH_RXQ`), not on RPQ. RPQ carries only TX
  release reports (`rtw89_pci_release_tx_skbs`, pci.c:644-697).
* RX descriptor (AX, `rtw89_core_query_rxdesc`, core.c:4070-4127; masks txrx.h:345-352):
  dword0 `RPKT_LEN` 13:0 (length of the C2H incl. its 8-byte header), `SHIFT` 15:14 (2-byte units),
  `RPKT_TYPE` 27:24 = **10 (`RTW89_CORE_RX_TYPE_C2H`)**, `DRV_INFO_SIZE` 30:28 (8-byte units),
  `LONG_RXD` bit 31 (32-byte vs 16-byte descriptor). On PCIe the RX buffer starts with a 4-byte
  `rtw89_pci_rxbd_info`; payload offset = 4 + shift*2 + drv_info*8 + (16 or 32)
  (pci.c:360-379; see track 03). Note: the AX parser never assigns `desc_info->shift` (only the BE
  parsers do, core.c:4141/4216), so rtw89 effectively assumes SHIFT=0 for AX.
* `rtw89_core_rx()` routes `pkt_type != WIFI` to `rtw89_core_rx_process_report`, which hands type 10
  to `rtw89_fw_c2h_irqsafe()` (core.c:4051-4068, 4490-4501). The skb data starts at the C2H header.

### 3.2 C2H header (8 bytes, `struct rtw89_c2h_hdr`, fw.h:3872-3881)

| Dword | Bits | Field |
|---|---|---|
| w0 | 1:0 | CATEGORY (0 TEST, 1 MAC, 2 OUTSRC) |
| w0 | 7:2 | CLASS |
| w0 | 15:8 | FUNC |
| w0 | 31:16 | not parsed by rtw89 |
| w1 | 13:0 | LEN — total C2H length **including** this 8-byte header (fw.c:2229-2231 subtracts the header) |
| w1 | 31:14 | not parsed |

Every C2H payload struct in rtw89 includes the header as w0/w1, so "w2" is the first payload dword.

### 3.3 Dispatch (fw.c:8053-8152, mac.c:6060-6252, phy.c:3397-4113)

1. `rtw89_fw_c2h_irqsafe` parses cat/class/func/len into `skb->cb`.
2. "Atomic" events are handled immediately in RX (NAPI/IRQ) context; everything else is queued to
   `c2h_queue` and processed from `c2h_work` under the wiphy lock. Atomic set
   (`rtw89_mac_c2h_chk_atomic` mac.c:6159-6201, `rtw89_phy_c2h_chk_atomic` phy.c:4054-4080):
   MAC/INFO REC_ACK & DONE_ACK; MAC/OFLD PKT_OFLD_RSP; MAC/OFLD SCANOFLD_RSP is pre-processed
   atomically (completes STOP wait) and then also queued; whole MAC classes MCC(4), MISC(9), MLO(0xC),
   MRC(0xE), WOW(3); MAC/AP PWR_INT_NOTIFY; OUTSRC RFK_LOG(8) funcs 0-5,0xC; OUTSRC RFK_REPORT(9)
   func 0.

### 3.4 C2H payload layouts relevant to a station

All dwords little-endian; w0/w1 = C2H header (§3.2).

**DONE_ACK** (`struct rtw89_c2h_done_ack`, fw.h:3898-3909)

| Dword | Bits | Field |
|---|---|---|
| w2 | 1:0 | H2C category being acked |
| w2 | 7:2 | H2C class |
| w2 | 15:8 | H2C func |
| w2 | 23:16 | H2C_RETURN (0 = success; for ADD_SCANOFLD_CH only bits 5:0 are meaningful) |
| w2 | 31:24 | H2C seq |

**REC_ACK** (`struct rtw89_c2h_rev_ack`, fw.h:3911-3919)

| Dword | Bits | Field |
|---|---|---|
| w2 | 1:0 / 7:2 / 15:8 | H2C cat / class / func |
| w2 | 23:16 | H2C seq (note: different position than in DONE_ACK) |

**C2H_LOG** (fw.h:3921-3940, fw.c:2220-2256): payload after the header is either plain ASCII
(printed verbatim) or a formatted record: `le16 signature = 0xA5A5`, `u8 feature` (bit2 =
PARA_INT: args are le32), `u8 syntax`, `le32 fmt_id`, `u8 file_num`, `le16 line_num`, `u8 argc`
(≤16), then args/raw string. Minimum formatted length 11 bytes. Formatted logs need the optional
LOGFMT suit of the FW file (fw.c:2134-2178); without it rtw89 silently drops formatted logs.

**PKT_OFLD_RSP** (fw.h:4206-4214): w2[7:0] PKT_ID, w2[10:8] PKT_OP (0 add, 1 del, 2 read),
w2[31:16] PKT_LEN (0 → failure).

**BCNFLTR_RPT** (`struct rtw89_c2h_mac_bcnfltr_rpt`, fw.h:3954-3962; handler mac.c:5389-5442):

| Bits of w2 | Field | Values |
|---|---|---|
| 7:0 | MACID | must match the vif macid |
| 9:8 | TYPE | 0 BEACON_LOSS, 1 RSSI, 2 NOTIFY (fw.h:273-277) |
| 11:10 | EVENT (for TYPE=RSSI) | 0 not changed, 1 HIGH, 2 LOW (fw.h:279-283) |
| 23:16 | MA | moving-average RSSI + 110 (`MAX_RSSI`, core.h:56); dBm = MA − 110 |

Beacon loss → `ieee80211_beacon_loss()` (unless scanning/off-channel) and re-send of the
beacon-filter config; RSSI/NOTIFY → `ieee80211_cqm_rssi_notify()`.

**RA status report** (`struct rtw89_c2h_ra_rpt`, fw.h:3963-3977; handler phy.c:3229-3389). Sent
unsolicited/periodically by FW for each macid under RA.

| Dword | Bits | Field (AX meaning) |
|---|---|---|
| w2 | 15:0 | MACID |
| w2 | 23:16 | RETRY_RATIO (BE only; rtw89 ignores on AX) |
| w2 | 31 | MCSNSS bit 7 (BE only) |
| w3 | 6:0 | MCSNSS (rate code, see below) |
| w3 | 9:8 | MD_SEL: 0 legacy, 1 HT, 2 VHT, 3 HE (`RTW89_RA_RPT_MODE_*`, core.h:3422-3428) |
| w3 | 12:10 | GILTF (HT/VHT: non-zero = short GI; HE: 3 or 5 → 0.8 µs, 2 or 4 → 1.6 µs, else 3.2 µs) |
| w3 | 14:13 | BW: 0 20, 1 40, 2 80, 3 160 MHz |
| w3 | 15, 16 | MD_SEL bit2 / BW bit2 (BE only) |

Rate code decode on AX (fw.h:4025-4031): legacy → hardware legacy rate index 0..11 (CCK 1/2/5.5/11,
OFDM 6..54, core.h:341-353); HT → MCS = code[4:0] (the `OLD_HT_RA_FORMAT` alternative is only for
8852A ≤ 0.13.29); VHT/HE → NSS = code[6:4] + 1, MCS = code[3:0]. rtw89 turns this into
`rate_info` for `sta_statistics` (`sinfo->txrate`, mac80211.c:1104-1105), computes a max A-MSDU length
from the bitrate (phy.c:25-54) and calls `ieee80211_sta_recalc_aggregates`.

**SCANOFLD_RSP**: Appendix B.

**RFK_REPORT / RFK_LOG** (FW-side calibration chips only; not expected on 8852B, §4.18):
RFK_REPORT STATE (OUTSRC class 9 func 0, `struct rtw89_c2h_rfk_report`, fw.h:5256-5260) = header +
`u8 state` (0 START, 1 OK, 2 FAIL, 3 TIMEOUT, 4 H2C_CMD_ERR; core.h:5480-5486) + `u8 version`.
RFK_LOG (OUTSRC class 8, func = calibration id) = header + a sequence of
`{u8 type (0 RUN_LOG, 1 RPT_LOG), le16 len, u8 content[len]}` records (fw.h:5080-5089,
phy.c:3849-3892). A new 8852B driver can log and drop both.

**Coex reports**: Appendix A.5.

### 4.4 RF table mirror — OUTSRC/8 (path A) or 9 (path B), func = page (fw.c:7114-7145, phy.c:1622-1740, 2004-2040)

During `rtw89_phy_init_rf_reg(noio=false)` (called from `rtw89_core_start`, core.c:6600), for each
path the radio table (FW-file element RADIO_A/B if present, else the built-in table) is applied with
`rtw89_phy_config_rf_reg_v1` (8852B, fw.c:1139-1143, rtw8852b_table.c:22875/22882):

* address 0xFE → 50 ms delay, nothing stored;
* otherwise write the RF register directly (RF mask 0xFFFFF), and **if addr ≥ 0x100** store the dword
  `(addr << 20) | data` into a host buffer (addresses < 0x100 are not mirrored).

After the path's table: send the stored dwords as H2C pages of up to `RTW89_H2C_RF_PAGE_SIZE = 500`
dwords (2000 bytes), up to `RTW89_H2C_RF_PAGE_NUM = 3` pages (max 1500 entries; entries beyond
1500 are dropped at store time with a warning, phy.c:1627-1636) (fw.h:4588-4594, phy.c:1644-1670).
Pages are sent in order 0, 1, 2 with exactly the number of stored entries; the buffer index is
reset after each path. Header: cat 2, class 8 (path A) / 9 (path B),
**func = page index** (0, 1, 2), rack 0, dack 0, len = 4·count. Payload = the raw dword array.
(The built-in 8852B radio-A table contains 1410 entries with addr ≥ 0x100 across all
conditional branches, e.g. 0x10000, 0x10018; the number actually sent depends on the RFE/CV branch
selected.) Purpose inferred: FW keeps a copy of the extended RF settings (for its own restore/PS
use). rtw89 always sends it; a new driver should too.

into an addr-CAM slot (pairwise → first free of 0-1; group → 2-4; AES-CMAC/BIP → 5-6; WEP switches
the mode to ALL_UNI), then re-send the addr-CAM H2C (dctl sec-cam H2C is NULL on 8852B).
TKIP is refused (`hw_tkip_crypto = false` → software). IV is generated by mac80211
(`hw_sec_hdr = false` → `IEEE80211_KEY_FLAG_GENERATE_IV`), management TX is software-encrypted
(`hw_mgmt_tx_encrypt = false`). Key delete: clear the slot bit, re-send addr-CAM; the sec-CAM entry
itself is not rewritten ("clear valid bit in addr cam will disable sec cam", cam.c:555-556).

## 5. H2C ordering across the station lifecycle (8852B, rtw89 behaviour)

Notation: `MAC/c/f` = cat 1 class c func f; `OUT/c/f` = cat 2; `REG:x` = register mailbox message;
`[coex]` = coex notification; the H2Cs it may emit (often none while BT is off) are listed in Appendix A.4.

### 5.1 Power-on (`rtw89_ops_start → rtw89_core_start`, core.c:6565-6632)

(`rtw89_ops_add_interface` calls `rtw89_leave_ips_by_hwflags` first; with IPS the chip is powered
on lazily when leaving idle, ps.c:257-278, which runs `core_start` + `set_channel` + `mac_vif_init`.)

1. `rtw89_mac_preinit`, power on — no H2C.
2. `rtw89_mac_init` → `rtw89_mac_partial_init` → FW download: `MAC/3/0` FW header + FW_DL chunks;
   poll FW ready; `h2c_seq = 0`; `RTW89_FLAG_FW_RDY` set (fw.c:1963-2012, 106-136).
3. `sys_init`, `trx_init` (registers); `rtw89_mac_feat_init` (no H2C: BA-CAM users only for
   BACAM_V1, mac.c:4082-4102).
4. **`MAC/9/0x14` OFLD_CFG** (seq 0 → REC_ACK forced) (mac.c:4393).
5. `rtw89_btc_ntfy_poweron` — no H2C (counter only).
6. BB/RF register init; **`OUT/8/p` RF_REG_A pages, then `OUT/9/p` RF_REG_B pages** (core.c:6600).
7. `rtw89_btc_ntfy_init(BTC_MODE_NORMAL)` — coex register init, then coex H2Cs: MREG_TABLE, REPORT_EN, SLOT_TABLE, DRV_INFO INIT, DRV_INFO CTRL, CX_POLICY, BT_WL_CH_INFO, DRV_INFO ROLE (Appendix A.4).
8. `rtw89_phy_dm_init` → `rtw8852b_rfk_init`: DACK [coex rfk start/stop], RX-DCK [coex rfk] +
   `REG:SCH_TX_EN` stop/resume.
9. `rtw89_hci_start`; `RTW89_FLAG_RUNNING` set (C2Hs are processed from now on).
10. `rtw89_btc_ntfy_radio_state(WL_ON)` — normally no H2C.
11. **`MAC/0/0` LOG_CFG** (comp 0).
12. `rtw89_fw_h2c_init_ba_cam` (no-op), TAS timer (no-op on AX).

### 5.2 add_interface (station; mac80211.c:169-240 → 107-148 → mac.c:5044-5084)

1. (power-on if needed, §5.1)
2. macid/port allocation (first: macid 0, port 0), `rtw89_vif_type_mapping(assoc=false)` → NO_LINK.
3. `rtw89_mac_port_update` (registers).
4. `rtw89_mac_dmac_tbl_init`, `rtw89_mac_cmac_tbl_init` (indirect register writes, not H2C).
5. **`MAC/9/0x08` MACID pause** (unpause macid 0).
6. **`MAC/8/4` role maintain CREATE**.
7. **`MAC/8/0` join info, OP=disconnect, NO_LINK**.
8. `rtw89_cam_init` (allocate BSSID-CAM + addr-CAM).
9. **`MAC/6/0` addr-CAM** (VALID=1, NO_LINK, SMA=vif MAC, TMA/BSSID = zero).
10. **`MAC/5/2` default CMAC table** (macid 0).
11. (default DMAC table: NULL on 8852B.)
12. `rtw89_btc_ntfy_role_info(BTC_ROLE_START)` — coex DRV_INFO ROLE (+ BT_WL_CH_INFO `01 01 20` for the default 2.4 GHz ch 1 context).
13. mac80211 then typically issues `conf_tx` ×4 → **`MAC/9/0x0F` EDCA ×4** (and again for
    ERP_SLOT changes).

### 5.3 Scan

**SW scan** (what a new minimal driver would use; mac80211.c:1231-1269, core.c:6969-7030):
* `sw_scan_start`: `rtw89_leave_lps`; `rtw89_btc_ntfy_scan_start` [coex];
  `rtw8852b_rfk_scan(start)` (registers); interrupt-mitigation recalc; EDCCA config; **`MAC/6/0`
  addr-CAM** with SMA = scan MAC (INFO_CHANGE).
* Each channel (`config(CHANGE_CHANNEL)` → `rtw89_set_channel`, core.c:531-580, mac80211.c:74-104):
  `REG:SCH_TX_EN` stop → channel/BB/RF/TX-power registers → `REG:SCH_TX_EN` resume; on band change
  `rtw89_btc_ntfy_switch_band` [coex] and `rtw8852b_rfk_band_changed` (TSSI scan, registers).
* `sw_scan_complete`: **`MAC/6/0` addr-CAM** with SMA = vif MAC; `rfk_scan(false)`;
  `rtw89_btc_ntfy_scan_finish` [coex].
* No scan-offload H2C.

**HW scan** (what rtw89 actually uses on this FW because `SCAN_OFFLOAD` is set): Appendix B.

### 5.4 Authentication / association (station)

Order of mac80211 callbacks for a connection and the H2Cs rtw89 emits:

1. `link_info_changed(BSS_CHANGED_BSSID)` → **`MAC/6/0` addr-CAM (INFO_CHANGE)** with the new
   BSSID in the BSSID-CAM part (mac80211.c:771-776).
2. Channel context assignment / channel config → `rtw89_set_channel` (`REG:SCH_TX_EN` ×2, coex band
   ntfy).
3. `sta_state NOTEXIST→NONE` (AP STA; macid = vif macid) → `rtw89_core_sta_link_add`
   (core.c:5656-5718): regd 6 GHz recalc; `rtw89_btc_ntfy_role_info(STA_CONN_START)` [coex];
   `rtw89_chip_rfk_channel` = host RFK (RX-DCK, IQK, TSSI, DPK with `REG:SCH_TX_EN` pairs and
   [coex rfk] ntfys) then **`OUT/0xA/2` RF get-MCC-channel notify**; DIG suspend (registers). Then
   `rtw89_fw_h2c_init_trx_protect` (no-op on AX).
4. `NONE→AUTH`: nothing.
5. `AUTH→ASSOC`: deferred for station (mac80211.c:951-956).
6. `vif_cfg_changed(BSS_CHANGED_ASSOC, assoc=1)` → `rtw89_station_mode_sta_assoc` →
   `rtw89_vif_type_mapping(assoc=true)` (INFRA, trigger=HE) → `rtw89_core_sta_link_assoc`
   (core.c:5799-5891):
   1. **`MAC/5/2` assoc CMAC table** (macid 0).
   2. **`MAC/8/0` join info, OP=connect, INFRA**.
   3. **`MAC/6/0` addr-CAM (CON_DISCONN)**: NET_TYPE=2, AID, TF_TRS, TMA = AP address.
   4. **`OUT/1/0` RA MACID cfg** (`rtw89_phy_ra_assoc`, UPD_ALL=1, CSI if AP is beamformer).
   5. `rtw89_mac_bf_assoc` / BF monitor (registers).
   6. `rtw89_btc_ntfy_role_info(STA_CONN_END)` [coex]; UL-TB / beacon-track setup (registers).
   7. **Packet offload ADD ×3 (PS-Poll, Null, QoS-Null) — each waited — then `MAC/0/1` general pkt**.
   8. **`MAC/9/0x1E` beacon filter cfg (connect)**.
   9. DIG resume.
   Then `__rtw89_ops_bss_assoc`: BSS color, UL-TB offset, `rtw89_mac_port_update`, OBSS narrow-BW RU
   (all registers).
7. `ASSOC→AUTHORIZED`: nothing.
8. `set_key` (PTK, GTK, optionally IGTK): per key **`MAC/0xA/1` sec-CAM** (×2 for 256-bit keys) then
   **`MAC/6/0` addr-CAM (INFO_CHANGE)**; coex EAPOL notification (work item).
9. `conf_tx` for the AP's WMM parameters → **`MAC/9/0x0F` ×4**.

Steady state (per 2 s `rtw89_track_work`): **`MAC/9/0x20` TP offload**, **`OUT/1/0` RA update
(UPD_MASK=1)**, coex traffic ntfy when the traffic level changes. Per beacon: **`MAC/9/0x1F` RSSI
offload**. FW → host: periodic RA reports, BCNFLTR reports, coex reports, DONE/REC_ACKs.

### 5.5 A-MPDU

* `AMPDU_TX_START`: returns `IEEE80211_AMPDU_TX_START_IMMEDIATE`, no H2C.
* `AMPDU_TX_OPERATIONAL` / `TX_STOP_*`: no H2C on 8852B (AMPDU CMAC op NULL); register-based agg
  limit.
* `AMPDU_RX_START`: **`MAC/0xC/0` BA-CAM valid** (if a static entry is available).
* `AMPDU_RX_STOP`: **`MAC/0xC/0` BA-CAM invalid**.

### 5.6 Disconnect (mac80211 moves the STA down AUTHORIZED→…→NOTEXIST; keys are removed via
`set_key(DISABLE_KEY)` → addr-CAM update; BSS_CHANGED_ASSOC(0) aborts an ongoing HW scan only)

1. `ASSOC→AUTH` (`rtw89_core_sta_link_disassoc`, core.c:5720-5737): **`MAC/9/0x1E` beacon filter
   cfg (connect=0)**; beacon-track reset.
2. `AUTH→NONE` (`rtw89_core_sta_link_disconnect`, core.c:5739-5782): BF disassoc (registers);
   `rtw89_vif_type_mapping(false)` (NO_LINK); **packet offload DEL ×3 (waited)**;
   **`MAC/5/2` assoc CMAC table**; **`MAC/8/0` join info OP=disconnect**; **`MAC/6/0` addr-CAM
   (CON_DISCONN, NO_LINK, AID 0)**.
3. `NONE→NOTEXIST` (`rtw89_core_sta_link_remove`, core.c:5894-5920): regd recalc;
   `rtw89_btc_ntfy_role_info(STA_DIS_CONN)` [coex].
4. `flush(drop)` from mac80211 may emit **`MAC/9/0x1B` pkt drop** ×4 (only for STAs still in the
   assoc list).

### 5.7 remove_interface (mac80211.c:150-167, 243-278; mac.c:5086-5101)

1. `rtw89_btc_ntfy_role_info(BTC_ROLE_STOP)` — coex DRV_INFO ROLE.
2. **`MAC/8/4` role maintain REMOVE**.
3. `rtw89_cam_deinit` (valid flags cleared, indexes freed).
4. **`MAC/6/0` addr-CAM** with VALID=0 and BSSID_VALID=0.
5. macid/port freed; if idle → IPS (`rtw89_enter_ips` → `rtw89_mac_vif_deinit` again + `core_stop`).

### 5.8 Power-off (`rtw89_core_stop`, core.c:6634-6673)

`rtw89_btc_ntfy_radio_state(WL_OFF)` [coex], clear RUNNING, `rtw89_btc_ntfy_poweroff` [coex],
flush (`rtw89_mac_flush_txq(drop)` may use pkt-drop H2C), HCI stop, MAC power off. No dedicated
"FW shutdown" H2C.

## 7. Minimal-driver notes (mandatory vs optional)

Mandatory for traffic in station mode (inferred from what rtw89 always sends; no experiment done):
OFLD_CFG (init), RF_REG mirror (init), MACID unpause, role maintain, join info (disconnect at
add_interface, connect at assoc), addr-CAM (with correct SMA/BSSID/AID/NET_TYPE), default + assoc
CMAC tables, RA MACIDCFG at assoc (FW does rate adaptation; DISDATAFB=1 in the CMAC table means the
host must give RA a mask), EDCA per AC, register SCH_TX_EN handshake around channel switches and host
RFK, RF get-MCC-channel notify after RFK, sec-CAM + addr-CAM for HW crypto, BA-CAM for RX
reordering offload (or accept dynamic BA CAM).

Optional: FW log cfg; general-pkt + packet offload; beacon filter/RSSI/TP offload (use mac80211
SW beacon-loss instead); pkt drop on flush; TX-time CMAC; periodic RA refresh (recommended to keep
the RSSI floor mask behaviour); coex (see Appendix A for what the FW does without it); HW scan.

Skip entirely: beacon update, LPS/IPS/PS, P2P, MCC/MRC, WoW, DBCC, CPU exception, TX duty,
FW RFK offload.

## Appendix A — Coex (BTC) H2C/C2H on 8852B 0.29.29.18

Scope: only what is sent as H2C and what arrives as C2H; the coex register programming (GNT,
PTA, scoreboard) belongs to the coex/MAC-init track and is only summarised in A.6.

### A.1 Version selection

`rtw89_coex_recognize_ver()` (coex.c:11856-11882, called after FW parsing) walks
`rtw89_btc_ver_defs[]` (coex.c:134-259) and takes the first entry with the same chip id and
`fw_ver_code <= FW version`. For 0.29.29.18 (= 0x001D1D12) the {RTL8852B, 0.29.29.0} entry
(coex.c:216-222) is chosen: fcxbtcrpt 105, fcxtdma 3, fcxslots 1, fcxcysta 5, fcxstep 3,
fcxnullsta 2, fcxmreg 2, fcxgpiodbg 1, fcxbtver 1, fcxbtscan 2, fcxbtafh 2, fcxbtdevinfo 1,
fwlrole 2, frptmap 3, fcxctrl 1, fcxinit 0, fwevntrptl 0, fwc2hfunc 1, drvinfo_type 0,
info_buf 1800, max_role_num 6, fcxosi 0, fcxmlo 0, bt_desired 7.

### A.2 Transport

All coex H2Cs: cat 2 (OUTSRC), class 0x10 (`BTFC_SET`), func = `enum rtw89_btc_btf_set`
(fw.h:2346-2371): 0 REPORT_EN, 1 SLOT_TABLE, 2 MREG_TABLE, 3 CX_POLICY, 4 GPIO_DBG, 5 DRV_INFO,
6 DRV_EVENT, 7..9 BT reg access, 10 BT_WL_CH_INFO, 11 BT_INFO_REPORT, 12 BT_IGNORE_WLAN_ACT,
13 BT_TX_PWR, 14 BT_LNA_CONSTRAIN, 15.. (query/PSD/test/IO-offload).

* Generic path `_send_fw_cmd` (coex.c:877-913) → `rtw89_fw_h2c_raw_with_hdr` with rack=0,
  dack=1 (fw.c:7957-7986). Refused if length is 0 or > 2020 (`BTC_H2C_MAXLEN`, coex.h:10), if
  coex `init_ok` is 0, or if WL is in RF-off/LPS-RF-off both before and now.
* DRV_INFO builders `rtw89_fw_h2c_cxdrv_*` (fw.c:5726-6400) call `rtw89_h2c_tx` directly with
  rack=0, dack=0 and bypass those gates. DRV_INFO payload starts with `{u8 type, u8 len}`
  (`len` = payload − 2); types (fw.h:2373-2388): 0 INIT, 1 ROLE, 2 DBCC, 3 SMAP, 4 RFK, 5 RUN,
  6 CTRL, 7 SCAN, 8 TRX, 9 TXPWR, 10 FDDT, 11 MLO, 12 OSI.
* No coex H2C is ever waited on; coex never needs a C2H to make progress. The only blocking step
  is a register poll of the BT scoreboard (up to 100 ms, 40 µs step) at WL-RFK start
  (coex.c:8463).

| traffic change (`rtw89_btc_ntfy_wl_sta`, from track work) | CX_POLICY/ROLE only if changed. |
| `radio_state(WL_OFF)` (core.c:6646) | REPORT_EN with all reports off (`05 00000000 00000000`), CX_POLICY if changed, BT_WL_CH_INFO if it was 2.4 GHz-linked, DRV_INFO ROLE. |
| `rtw89_btc_ntfy_poweroff` | none. |

### A.5 Coex C2H

OUTSRC classes 0x10..0x17 go to `rtw89_btc_c2h_handle`, which only processes class 0x12
(`BTFC_FW_EVENT`) (coex.c:8741-8760); they are not atomic (queued to `c2h_work`). Funcs for
fwc2hfunc 1: 0 RPT, 1 BT_INFO (8 bytes, byte1 must be 6), 2 BT_SCBD, 3 BT_REG, 4 CX_RUNINFO,
5 BT_PSD, 6 BT_DEV_INFO (ignored), 7 BUF_OVERFLOW, 8 LOOPBACK (coex.c:8683-8736). RPT payload =
sequence of `{u8 type, le16 len, u8 data[len]}` records (header 3 bytes, ≤ 1800 bytes total);
record types for fwevntrptl 0 (coex.c:1383-1396): 0 CTRL, 1 TDMA, 2 SLOT, 3 CYSTA, 4 STEP,
5 NULLSTA, 6 MREG, 7 GPIO, 8 BT_VER, 9 BT_SCAN, 10 BT_AFH, 11 BT_DEV, 12 TEST; a record whose length
differs from the expected struct size is discarded. All of this is diagnostic/BT-state input;
nothing in the WL datapath depends on it.

### A.6 Is coex mandatory for WiFi-only?

From the host code: no H2C is required for WL to own the antenna — that is done by registers in
`btc_init_cfg` / `_set_ant` (GNT override 0x77007700 through the LTE-indirect register 0x38 =
"WL granted, BT not", control path `0x70` bit 26 = WL, PTA/PLT setup, scoreboard 0xAC). All
`ntfy_*` are void and H2C failures are only counted. Firmware-side defaults without coex H2Cs
cannot be determined from host code. The coex-init H2C set above (INIT, CTRL, SLOT_TABLE,
CX_POLICY OFF_BT, ROLE, MREG/REPORT_EN) is cheap and fire-and-forget; recommended if BT may be
active (the machine's BT is on this chip).

## Appendix B — HW scan offload (AX path, as rtw89 uses it on this FW)

Not needed for a SW-scan driver (§5.3). Documented because rtw89 selects it on 0.29.29.18
(`SCAN_OFFLOAD`), and because `SCAN_OFFLOAD` + `BEACON_FILTER` also make rtw89 use real channel
contexts instead of `ieee80211_emulate_*chanctx` (core.c:7557-7570). A driver that wants SW scan
should not register `hw_scan` (or return 1 from it, which rtw89 does when the feature is missing,
mac80211.c:1290-1292) and should use emulated chanctx so channel changes arrive via
`config(CHANGE_CHANNEL)`.

### B.1 Constants (fw.h:329-350)

Channel time 45 (`RTW89_CHANNEL_TIME`), DFS 105, off-channel budget 100 (`RTW89_OFF_CHAN_TIME`),
P2P 105, dwell 20 (passive/DFS), per-entry size 28 bytes (`RTW89_MAC_CHINFO_SIZE`), guard 4 →
`RTW89_SCAN_LIST_LIMIT_AX = 2048/28 − 4 = 69` channel entries per ADD_SCANOFLD_CH H2C. wiphy
advertises `max_scan_ssids = 8`, `max_scan_ie_len = 512`, random-MAC scan (core.c:7399-7447).
Band codes 0 = 2.4 GHz, 1 = 5 GHz.

### B.2 Start sequence (`rtw89_ops_hw_scan` mac80211.c:1279-1322 → `rtw89_hw_scan_start` fw.c:9311-9377 → `rtw89_hw_scan_offload(true)` fw.c:9471-9510)

1. Save operating channel; decide `connected` (any link with non-zero BSSID); pick scan MAC
   (random if `NL80211_SCAN_FLAG_RANDOM_ADDR`).
2. Probe-request templates: for each SSID (≤ 8) × each band (2.4, 5): `ieee80211_probereq_get()` +
   band IEs + common IEs → **PACKET_OFLD ADD** (MAC/9/1, waited) (fw.c:8377-8450).
3. Build the channel list (`rtw89_hw_scan_prep_chan_list_ax`, fw.c:8857-8942): per requested channel
   period = `req->duration` ?: 45 ms (105 for P2P); type DFS (radar/no-IR) or ACTIVE; when
   connected, insert an OPERATE entry (45 ms, or `duration` if mandatory) whenever accumulated
   off-channel time + period would exceed 100 ms.
4. `ieee80211_stop_queues`; clear `B_AX_TSF_UDT_EN` (bit 3) of `R_AX_PORT_CFG_P0` 0xC400 for the
   port (mac.c:4673-4683); `rtw89_core_scan_start(hw_scan=true)` (addr-CAM with scan MAC, coex,
   EDCCA max, RFK scan notify, interrupt mitigation off); RX filter clears `A_BCN_CHK_EN` (bit 7),
   `A_BC` (bit 2), `A_A1_MATCH` (bit 1) of `R_AX_RX_FLTR_OPT` 0xCE20; chanctx pause; DIG suspend.
5. **ADD_SCANOFLD_CH** (MAC/9/0x16, rack=1, dack=1) with ≤ 69 entries, waited for DONE_ACK
   (return & 0x3F must be 0), then **SCANOFLD start** (MAC/9/0x17, rack=1, dack=1) waited for
   DONE_ACK; afterwards obsolete queued scan C2Hs are purged (mac.c:1761-1782).

### B.5 SCANOFLD_RSP C2H (MAC class 1 func 9; fw.h:4040-4065; mac.c:5281-5390, 6130-6157)

| DW | Bits | Field |
|---|---|---|
| w2 | 7:0 | PRI_CH |
| w2 | 19:16 | RSN: 0 DWELL, 1 PRE_TX, 2 POST_TX, 3 ENTER_CH, 4 LEAVE_CH, 5 END_SCAN, 6 REPORT, 7 CHKPT, 8 ENTER_OP, 9 LEAVE_OP (fw.h:228-239) |
| w2 | 23:20 | STATUS: 0 NOTIFY, 1 SUCCESS, 2 FAIL |
| w2 | 31:24 | PERIOD (actual) |
| w5 | 3:0 / 7:4 / 25:24 / 26 | TX_FAIL / AIR_DENSITY / BAND / MAC_IDX |
| w6..w8 | | BE-only fields |

Handling: atomic stage tags the event with the current 2-bit scan seq (incremented by every REC_ACK
of a SCANOFLD H2C) and completes the STOP wait on END_SCAN; deferred stage:
LEAVE_CH/LEAVE_OP → stop queues if leaving the op channel (else collect noise);
ENTER_CH/ENTER_OP → update the driver's notion of the current channel (RX `rx_status` band/freq)
and wake queues on the op channel; END_SCAN → send the next ≤ 69-entry batch + new START, or
finish (`rtw89_hw_scan_complete`: restore channel via `rtw89_set_channel`, RX filter, addr-CAM
SMA, `ieee80211_scan_completed`, wake queues, TSF_UDT_EN back on, DIG resume, PACKET_OFLD DEL
for every probe template, null-data PM=0 to the AP). Other reasons ignored.

## Open questions / uncertainties

* The forced REC_ACK on every 4th H2C (fw.c:1613) is not explained in code; unknown whether the FW
  stalls without it. Keep it.
* Semantics of the fixed OFLD_CFG payload (`09 00 00 00 5e 00 00 00`) are undocumented.
* Why the RF table entries with address ≥ 0x100 are mirrored to FW is not stated; assumed to be FW
  restore data.
* C2H header bits other than cat/class/func/len (w0[31:16], w1[31:14]) are not parsed by rtw89;
  their meaning (likely C2H seq / ack bits) is unverified.
* The RA status report period is FW-defined; rtw89 has no H2C to configure it.
* Packet-offload DEL completion requires `pkt_len != 0` in PKT_OFLD_RSP (same check as ADD); FW
  behaviour for DEL is assumed to report the old length.
* The AX RX-descriptor parser never reads SHIFT (core.c:4103 uses an unassigned field); assume 0.
